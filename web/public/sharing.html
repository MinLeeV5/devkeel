// Prompt Engineering

Prompt：把任务说清楚

USER INPUTphone-login.feature
目标

给现有登录页增加手机号 + 短信验证码登录。

约束

复用项目现有组件和接口，只改前端，不引入第二套设计语言。

输出

完成代码、测试与变更说明，并给出可以复跑的验证结果。

01 · TARGET

目标

描述用户最终获得的能力。

02 · BOUNDARY

约束

明确复用范围与不可越过的边界。

03 · DONE

输出

把完成声明变成可检查的交付物。

它解决：单次表达减少歧义，让 Agent 更容易沿着正确方向起步。
类比：网页端 ChatGPT只有对话，没有你的项目；除非主动提供，否则它完全不知道已有代码、组件、接口和测试约定。

参考：OpenAI · Prompt engineering best practices

DevKeel 展开 · Rules

Rules：让项目事实成为 Agent 会加载的执行条件

STEP 01 · DOMAIN SIGNALS

识别领域与技术栈

从依赖、目录、配置和脚本判断项目属于什么领域，先确定后续扫描边界。

完成信号得到项目类型、核心技术栈与验证入口的可信画像。
主要输入package.json · lockfile · config
判断重点运行时、框架、构建方式与测试命令
避免误判不把模板、示例或历史产物当成主项目
STEP 02 · CODE SIGNALS

扫描真实代码

从入口和直接依赖向外展开，用真实实现寻找架构边界、现有模式与常用命令。

完成信号形成带代码位置和命令依据的项目事实索引。
优先读取入口文件、命中符号与直接依赖
寻找模式模块边界、错误处理、测试接缝与命名约定
控制范围先小范围命中，再按证据扩展扫描
domain-init · OUTPUT

提炼项目能力

在 docs 中维护项目事实，在 rules 中保留执行约束，并提炼专项方法与角色。

完成信号AGENTS.md 成为短地图，专项知识按任务加载。
知识与约束docs/ · .harness/rules/
方法.harness/skills/
角色.harness/agents/
STEP 04 · HUMAN GATE

人工审查后写入

先确认内容准确、范围清晰、命令可执行，再把约束持久化到仓库。

完成信号同主题内容增量合并、已有约定得到保留，并能在任务中按需读取。
审查内容事实准确性、ownership、适用范围与例外
写入原则只补缺口，不复制宿主层已有约束
运行验证用真实任务确认地图路由和按需加载

DevKeel 展开 · Verify

Verify：先搭建可执行反馈，再要求 Agent 自证完成

STEP 01 · CURRENT STATE

检测现状

先识别已有测试框架与运行入口，避免把“没找到”误判成“没有”。

完成信号列出可复用基础、真实缺口和最邻近的验证命令。
扫描对象依赖、配置、锁文件、scripts 与测试目录
优先复用已有框架、命名方式和测试接缝
保护边界不覆盖现有配置，不重复安装依赖
STEP 02 · CONFIRM GAP

确认缺口

把检测结果变成可选择的补齐项，由用户确认本轮需要建立哪些反馈能力。

完成信号范围、安装动作和保留项明确，不对环境做隐式扩张。
可能缺口框架、配置、示例、脚本或运行说明
用户确认哪些本轮补齐，哪些沿用或暂缓
风险检查版本兼容、锁文件变化与 CI 影响
STEP 03 · TEST SCAFFOLD

增量补齐

只添加缺失部分，让最小测试示例和标准命令可以立即执行、重复运行。

完成信号framework + config + example + scripts 形成最小闭环。
安装选择与现有运行时兼容的框架版本
配置增量接入，不覆盖项目已有设置
示例提供一条能稳定通过的邻近反馈
STEP 04 · PROJECT CAPABILITY

维护验证知识与角色

在 docs 中维护命令与说明，复用项目已有测试规则，与 domain-init 共用同一套验证知识。

完成信号测试规范与验证职责不再依赖聊天中的临时说明。

发现入口由 AGENTS.md 指向当前任务需要的验证能力

先邻近运行，再按风险扩大

验证从最接近改动的反馈开始，逐步扩展到构建、预览和 Review。

完成信号完成声明附带可复跑命令、关键输出和审查证据。

// Loop Engineering

Loop 有两个时间尺度：任务内纠偏，任务间进化

01 · INNER LOOP · 分钟级

目标 → 实现 → 验证 → 判断

一次执行内：未通过就定向修正，通过后证据化交付。
↓ 交付进入任务间闭环
02 · OUTER LOOP · 迭代级

复盘 → 提炼 → 更新 DevKeel → 下一次任务

跨任务持续：新规则被自动加载并验证。
闭环不是无限重试：必须有可判定信号、修正策略、停止条件和人类升级入口。
