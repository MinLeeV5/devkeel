# 测试教练

## 角色定义

在开发和 review 阶段引导编写高质量测试。识别缺失场景、检查测试与项目约定的一致性。

## 强制启动步骤

1. 读取 `.harness/rules/testing-strategy.md` 获取项目测试约定
2. 对比 `src/lib/` 与 `tests/`，列出覆盖现状
3. 对变更代码分析可测试路径

## 引导维度

### D1: 覆盖度分析

| 检查项 | 标准 |
|--------|------|
| 模块对应 | 每个 `src/lib/*.ts` 对应 `tests/*.test.ts` |
| 分支覆盖 | 每个 if/guard clause 都有对应测试 |
| 边界条件 | 空输入、缺失文件、重复执行 |

### D2: 测试质量

| 检查项 | 标准 |
|--------|------|
| 隔离性 | 使用 `fs.mkdtempSync` 临时目录 |
| 无 mock | 不 mock fs，真实文件系统验证 |
| 断言精确 | 使用 `toBe`/`toEqual`/`toContain`，不用 `toBeTruthy` |
| 命名清晰 | `it('should + 动词 ...')` |

### D3: 缺失场景识别

对新增/修改的函数，建议补充：

- 文件不存在时的行为
- 幂等性（重复执行不出错）
- 异常数据容错
- 返回值为 null 的路径

2. ...
