# MR/PR 流程

本文件承载 `commit` skill 的 MR/PR 阶段，授权边界沿用 `SKILL.md`。仅请求方案或准备描述时保持只读。

## 范围与准备

1. 从当前任务、仓库规范和远端信息确认目标仓库、源分支与目标分支，核对分支间的完整差异；
   不将其他任务的提交带入 MR/PR。
2. 已有必要提交或推送时直接复用；缺少时按 `SKILL.md` 的提交与推送流程完成已授权动作，
   不重复询问创建 MR/PR 已包含的必要授权。
3. 检查是否已有对应源分支与目标分支的 MR/PR；存在时核对其范围并复用，避免重复创建。

## 标题与描述

标题格式与 commit 一致：`<type>(<scope>): <subject>`，subject 使用中文。

描述以目标分支的实际 diff 为依据，说明问题与改后行为，采用仓库模板；无模板时按下表组织，
篇幅与改动相称，无关章节省略。

| 章节 | 说明 |
| :--- | :--- |
| 变更概述 | 说明 MR/PR 的目的、范围与改后行为 |
| 关联 | issue / 需求文档（如有） |
| 变更类型 | feat / fix / refactor / docs / style / test / chore |
| 测试说明 | 已执行的手动步骤或自动化用例及结果、未验证项 |
| 其他 | 破坏性变更、配置变更、依赖升级（如有） |

## 粒度

- 一 MR/PR 一目的：避免多功能混合。
- 分支内 commit 保持原子化；获准合并时，按仓库策略及平台支持选择是否 squash。

## 创建与核对

使用仓库对应的平台工具创建：GitLab 使用 `glab mr create`，GitHub 使用 `gh pr create`；
显式指定已确认的源分支、目标分支、标题与描述。多行描述优先使用结构化参数，使用 `gh` 时
将完整正文写入临时文件并通过 `--body-file` 传入，保留真实换行。

创建或复用后，从远端核对：

- [ ] 仓库、源分支、目标分支及完整 diff 符合已确认范围
- [ ] 标题与描述符合规范，验证结果与未验证项如实记录
- [ ] 已获得 MR/PR 链接，流水线与审批状态已核对；排队或未运行不记为通过

交付 MR/PR 链接和实际状态。创建完成后停止；用户已明确授权合并时，按项目要求和平台门禁
继续执行并核对最终合并结果。
