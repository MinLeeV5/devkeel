# 模式策略

## 模式定义

### `fast`

适用于：

- 单域改动
- 文件数少
- 没有配置、契约、集成、数据库等高风险信号

默认策略：

- 优先请求更轻量模型
- 重点查 `P0/P1`
- 输出更短

### `deep`

适用于：

- 跨领域改动
- 涉及接口契约、DTO、错误码、默认值
- 涉及配置、消息队列、WebSocket、流式处理
- 涉及数据库 Schema、ORM、持久层
- 涉及 E2E、关键业务旅程、发布前确认

默认策略：

- 请求高端推理模型
- 完整说明高置信 findings、验证缺口和 residual risk

### `auto`

默认模式。先判断是否满足 `fast` 条件；只要不满足，就进入 `deep`。

## `auto -> fast` 的建议阈值

同时满足以下条件时，优先落到 `fast`：

- 只命中一个领域
- changed files 不超过 8 个
- 不命中高风险路径或关键词（dto、mapper、config、mq、websocket、e2e、stream 等）

## 自动升级为 `deep` 的信号

即使用户显式要求 `fast`，只要发现以下任一信号，也要升级为 `deep`：

- 跨领域改动
- DTO / 错误码 / 默认值变化
- 配置变更
- 消息队列 / WebSocket / 流式处理
- 数据库 Schema / ORM / 持久层
- E2E 或关键业务路径变更
