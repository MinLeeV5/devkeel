# 产出格式规范

## 内容分类与归属

根项目与子项目遵循相同规则；知识写入各自 `docs/`，跨项目通过链接引用。

| 内容 | 产出 |
|------|------|
| 全局执行契约、路由、读取条件 | AGENTS.md |
| 简短执行约束，包含低频硬约束 | .harness/rules/ |
| 项目背景、架构、原理、开发说明、详细示例 | docs/ |
| 可复用操作流程 | .harness/skills/ |
| 被调度角色及执行职责 | .harness/agents/ |

OpenSpec 内容保留在主仓库 `openspec/`；项目文档引用相关规范，不复制其正文。
配置和 scripts 是参数、命令与门槛的执行事实源。

按主题检索已有文件，优先更新原文件。R4 与 verify-init 复用同一测试规则和文档：如已有
`testing-strategy.md` 就继续维护它；仅缺失时创建 `.harness/rules/testing.md` 和 `docs/testing.md`。
冲突须定位配置与已确认决定，不能靠新建另一份文件绕过。

## Docs 格式

标题说明主题；按实际需要记录适用范围、当前事实、来源和相关入口，不强制章节数量。
命令注明运行目录并链接对应 scripts；详细示例注明用途，不把示意代码当作当前实现。

- `docs/README.md` 可作为按任务组织的索引，已有索引则复用。
- 文件名沿用项目惯例；项目概览、架构、开发与测试说明按需创建，不生成空目录和占位文档。
- AGENTS 的 `project` 槽位统一维护项目知识入口；rules 按需引用相关说明。只添加已存在文件
  的相对链接并注明读取条件，不要求每次遍历全部 docs。
- 已填槽位只保留正文，删除成对的 `harness:user` 边界注释与已用完的占位提示；未填槽位保留
  占位。后续按章节增量维护，保留相邻框架正文，不因标记消失而重建槽位或重复入口。
- 迁移先落目标内容，再核对来源、语义和链接，最后替换原文；有效执行约束仍保留在 rules。
- 已有用户内容增量合并；未经验证的建议与冲突先留在 review 中，不写成当前项目事实。

## Rule 格式

```yaml
---
description: <一句话描述，说明何时触发>
globs:
  - "**/*.ts"
  - "**/*.tsx"
---
```

正文要求：
- 写清适用条件与执行动作；保留权限、停止条件、例外和失败恢复语义。
- 约定来源须在代码、配置或已确认决定中可查证；不按数量或示例配额凑规则。
- 长解释与示例写入 docs，rule 保留必要的读取条件和链接。
- `description`/`globs` 表达适用范围；平台支持不同，不将其视为跨平台按需加载保证。

## Skill 格式

```yaml
---
name: <kebab-case>
description: <一句话描述，含触发词>
metadata:
  author: "domain-init"
  version: "1.0.0"
---
```

正文要求：
- 概述（何时使用、何时不使用）
- Hard Rules（不可违反的约束）
- 工作流程（步骤化）

技能由 `.claude/skills` 与 `.agents/skills` 整目录链接到 `.harness/skills` 后读取，新增或修改本仓库技能无需再次运行 `devkeel sync`；运行中会话是否刷新技能列表按平台行为处理，必要时重开会话。

共享流程写在 `SKILL.md`；Claude Code 原生选项按需要写入 frontmatter，Codex 展示信息和调用策略按需要放在技能包内的 `agents/openai.yaml`。平台执行说明仅在有实际差异时放入 `references/claude-code.md`、`references/codex.md`，入口按平台读取。不要依赖自定义 `triggers` 字段，使用 `description` 表达适用场景；保留手动调用，调用策略不能替代用户授权。

## Agent 格式

```yaml
---
name: <kebab-case>
description: <一句话描述角色和职责。说明何时被调度。>
model: sonnet
---
```

正文要求：
- 角色定义（你是什么、负责什么）
- 强制启动步骤（必须按顺序执行）
- 审查/执行维度（编号列表）
- 输出规则（blocker-first、条数限制、语言）

## 质量标准

| 标准 | 要求 |
|------|------|
| 内容归属 | 约束与知识分开，低频硬约束不丢失 |
| 文档引用 | 链接存在、读取条件明确、同主题复用 |
| 代码依据 | 约定必须能在项目代码中找到出处 |
| Skill 完整性 | 必须有「何时使用」和「Hard Rules」 |
| Agent 完整性 | 必须有「审查维度」和「输出规则」 |
| 禁止理想化 | 不输出与项目实际不符的规范 |
| 参考标杆 | 生成前必须 fetch 对应参考项目 |
