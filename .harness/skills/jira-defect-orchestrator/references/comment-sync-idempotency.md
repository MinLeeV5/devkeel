# Jira 评论同步幂等

## 何时加载

仅在以下任一情况出现时加载：

- 评论写入失败、超时，或工具返回结果不确定，需要重试
- 会话从中断、压缩或移交后恢复，无法确认上次同步结果
- 同一 Gate 或同一阶段结论可能已经回填

同步状态明确且确认是首次写入时，不要读取本文件。

## 回读优先

在重试或恢复写入前执行：

```bash
jira issue view <ISSUE-KEY> --raw
```

检查 `.fields.comment.comments[]`。需要快速浏览时可以使用：

```bash
jira issue view <ISSUE-KEY> --raw \
  | jq -r '.fields.comment.comments[]? | [.id, .author.displayName, .body] | @tsv'
```

不要回显认证 token，也不要把读取失败解释为“评论不存在”。

## 语义判重

不要对原始字符串做字节级比较。Jira 可能把 Markdown 转换为 wiki 标记，例如 `## 标题` 变成
`h2. 标题`，并改写列表、转义符和空白。

用以下两层语义键判断：

1. **阶段标题**：`根因分析` / `方案设计` / `已验证` / `关闭结论`，或等价的明确更新标题
2. **实质结论**：该阶段 1 到 3 条会影响决策的关键事实、选定方案或验证结果

比较时忽略 Markdown 与 Jira wiki 标记差异、列表符号、转义连字符和纯空白变化。

| 已有评论 | 动作 | 结果记录 |
| --- | --- | --- |
| 没有同阶段评论 | 添加完整的最小评论 | `added` |
| 同阶段且实质结论相同 | 跳过写入 | `skipped_duplicate` |
| 同阶段但结论有实质变化 | 只追加差量，标题使用“方案更新”“验证补充”等 | `added_delta` |
| 回读失败或仍无法判断 | 停止写入并报告控制面失败 | `blocked_unknown` |

若 `jira issue comment add` 超时或返回不确定结果，必须再次回读；只有确认不存在语义相同评论后才能重试。
