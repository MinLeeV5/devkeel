# D08 性能与资源

## 目标

选择适合领域的性能和资源指标，说明风险、目标、验证方式和取舍。不要把后端吞吐指标套到所有领域。

## 输出契约

- 关注指标：按领域选择，例如接口延迟、吞吐、首屏、交互延迟、启动耗时、内存、CPU、包体、电量、构建耗时。
- 目标或阈值：有明确业务目标时写数值；没有时写相对约束和验证方式。
- 资源风险：热点、阻塞、同步 IO、重复渲染、大对象、批量扫描、外部调用。
- 设计策略：缓存、分页、懒加载、批处理、并发控制、限流、资源释放。
- 验证方式：基准测试、性能测试、浏览器/桌面 profiling、日志或真实环境采样。

## 指标提示

- backend：接口延迟、吞吐、队列积压、连接数、存储压力。
- frontend：首屏、交互响应、渲染次数、包体、网络瀑布。
- desktop/mobile：启动耗时、内存、CPU、电量、包体、窗口或页面切换。
- cli：冷启动、大目录扫描耗时、网络等待、输出体积。

## 完成检查

- [ ] 指标与领域匹配。
- [ ] 目标和验证方式能被执行。
- [ ] 性能取舍没有牺牲关键正确性。
