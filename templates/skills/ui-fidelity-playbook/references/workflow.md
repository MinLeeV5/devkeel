# UI 高保真实现流程

本文档补充 `ui-fidelity-playbook` 的具体执行步骤。

## 1. 确认本轮实现范围

先回答：

- 本轮目标是整页、局部区块、弹窗、组件，还是宿主容器中的内容区？
- 只覆盖默认态，还是也覆盖切换态、异常态、空态、加载态？
- 设计意图展示的是一个静态节点，还是一整套交互流程？

如果范围不清晰，优先缩小到当前必须交付的最小闭环。

## 2. 确认运行时 ownership

先探索当前仓库，而不是根据截图猜：

- 当前页面挂在哪个路由上
- 当前页面是否运行在上层容器里
- 上层是否已经提供导航、窗口壳子、标签栏、骨架屏或操作区
- 当前页面是否只是大容器中的局部内容

如果截图看起来像整窗稿，但运行时页面只是内容区，优先实现内容区。

## 3. 获取设计事实

无论来源是 Figma、Sketch、截图还是线框，至少拿到以下事实：

- 本轮来源
- 可对照的视觉事实（设计稿/截图/线框）
- 资源资产
- 必要时的状态变体说明

来源为 Figma 时，用其 MCP 取结构化上下文效果最佳（见 SKILL.md「来源为 Figma 时的最佳实践」）。不要只凭截图做实现，也不要只凭结构化代码做实现。

## 4. 先拆层，再拆块

推荐拆法：

### 运行时层次
- 宿主层
- 页面层
- 组件层
- 浮层
- 状态层

### 页面内容块
- 顶部区域
- 主体区域
- 辅助说明区域
- 底部操作区域
- 条件显示区域

## 5. 优先识别高风险点

优先看这些：

- 外层容器尺寸和边界
- 垂直节奏和留白
- 横向对齐与分布
- 背景层、覆盖层、透层
- 图标和资源是否精确
- 阴影、圆角、边框是否影响整体观感
- 切换交互是否带来跳动
- 不同状态是否维持同一套结构关系

## 6. 分轮次实现

### 第一轮：结构骨架
目标是"对"，不是"像"。

检查：
- 区域归属是否正确
- 布局模型是否正确
- 显示/隐藏逻辑是否正确
- 内容容器是否在正确位置

### 第二轮：视觉收敛
重点：
- 尺寸
- 间距
- 字重字号
- 背景
- 圆角阴影
- 资源替换

### 第三轮：交互与状态收敛
重点：
- hover / active / disabled
- loading / empty / error
- tab / step / method 切换
- 条件展示逻辑
- 切换后是否保持合理布局

## 7. 运行时验证

至少做两类验证：

- 局部验证：离改动最近的测试或类型检查
- 运行时验证：在真实容器中观察最终效果

当页面依赖上层容器时，只看孤立页面通常不够。
