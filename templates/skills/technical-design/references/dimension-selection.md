# 技术设计维度选择

本文件只负责“什么时候选哪些维度、输出多深”。不要在这里写各维度的正文模板；维度输出契约以 `references/dimensions/Dxx-*.md` 为准。

## 输入信号

先从以下来源提取信号：

- 用户目标：要解决的问题、期望交付物、明确排除范围。
- 领域标签：frontend、backend、desktop、native-service、mobile、cli、sdk、devops、custom。
- 变更触点：UI、API、数据、运行时、权限、性能、发布、迁移、观测、兼容。
- 影响范围：单文件、单模块、跨模块、跨进程、跨系统、跨版本。
- 风险信号：敏感数据、外部契约、不可逆迁移、故障传播、资源压力、用户可见体验。

## 选择流程

1. 根据输入信号选择一个或多个 `domain-profiles/*.md`。
2. 合并 profile 中命中的维度行。
3. 对同一维度取最高优先级：`core > supporting > checklist > skip`。
4. 若一个维度被多个领域启用，选择原因必须列出所有主要触发点。
5. 只有 `core` 和必要的 `supporting` 才读取对应维度文件并展开正文。
6. `checklist` 落实到实际风险、验证或发布检查；`skip` 不进入最终输出。

## 内部记录

维度选择是内部决策步骤，不默认写入技术方案正文。内部记录使用以下字段即可：

- 维度：D01-D14 的编号和名称。
- 领域/触点：由哪些领域 profile 或变更触点启用。
- 优先级：`core / supporting / checklist / skip`。
- 选择原因：为什么本次需要展开或跳过。

内部记录不得复制到最终技术方案。最终文档直接呈现被选中的设计决策、边界、验证和风险，
不输出维度摘要、矩阵、优先级、skip 理由或覆盖证明。

## 约束

- 不要因为 profile 中出现某维度就强制展开；必须结合本次触点判断。
- 不要把后端指标套到前端、客户端或桌面端；D08 允许按领域换指标。
- 安全启用条件写在 profile 和本选择表中；D10 只定义启用后的输出契约。
- 多领域冲突时，以用户可见风险、外部契约和不可逆影响优先。
