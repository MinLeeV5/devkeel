# D02 架构边界与模块关系

## 目标

说明系统、模块、包、服务或组件之间的边界，以及依赖方向和候选方案取舍。

## 输出契约

- 当前结构：现有模块、依赖、入口和约束。
- 目标结构：变更后的模块关系或架构视图。
- 方案对比：存在多个合理方案时列出取舍；唯一方案要说明排除理由。
- 边界规则：哪些模块可以依赖哪些模块，哪些依赖禁止出现。
- 影响面：新增、修改、删除的主要模块和调用链。

## 可选工具

- C4：适合跨系统、跨容器或组件关系不清时。
- ATAM：适合候选方案和质量属性冲突明显时。
- 简表：适合单模块内部调整。

## 完成检查

- [ ] 读者能看出变更落在哪些模块。
- [ ] 依赖方向和边界违规风险已说明。
- [ ] 方案取舍有理由，不只写“推荐方案”。
