# D03 运行边界与职责归属

## 目标

用大白话说明：模块运行在哪里、谁负责什么、不负责什么。适合浏览器、服务端、桌面主进程、preload、renderer、CLI、本地脚本、worker、移动原生层等多运行时场景。

## 输出契约

- 运行位置：每个关键模块在哪个进程、线程、环境或宿主中运行。
- 职责归属：当前模块负责什么，上层壳子、下层服务或外部平台负责什么。
- 不负责清单：明确哪些能力不在当前层重复实现。
- 通信边界：跨进程、跨线程、跨网络或跨宿主的通信方式。
- 失败边界：某层失败时如何不把错误扩散到不该受影响的层。

## 常见提示

- Electron：主进程负责窗口和受控原生能力，preload 负责最小白名单桥接，renderer 负责 UI 和页面状态。
- Web：浏览器负责交互和本地状态，服务端或 BFF 负责可信数据和权限判断。
- CLI：命令进程负责参数、输出和本地文件，外部服务负责远端状态。
- SDK：调用方负责生命周期和配置，SDK 负责契约内行为和错误模型。

## 完成检查

- [ ] 每个关键模块都能回答“运行在哪里”。
- [ ] 每层负责什么、不负责什么写清楚了。
- [ ] 跨边界通信和失败传播有约束。
