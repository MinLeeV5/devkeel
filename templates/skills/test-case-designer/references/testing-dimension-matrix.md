# 测试维度矩阵

## 层次关系

```
需求输入（spec/brainstorm/design）
    ↓ 是测试用例的唯一来源
领域矩阵
    ↓ 决定"用哪些视角去审视这些需求"
测试点/测试用例
    ↓ 每条都必须回链到需求
```

矩阵中的维度不是"无条件扫描"，而是"当需求涉及该维度时，用这个视角深入展开"。未被需求触及的维度即使标 `●` 也不会产出测试点。

## 使用规则

1. **自动检测优先**：扫描项目信号，匹配领域列；用户可通过 `domain=xxx` 显式覆盖
2. **多领域取并集**：命中多个领域时，合并所有 `●` 和 `○`
3. **需求驱动启用**：
   - `●` 维度：分析需求时主动检查该视角，需求涉及则展开测试点
   - `○` 维度：仅当需求/spec 中显式提及相关场景时才展开
   - `—` 维度：跳过，不检查
4. **向后兼容**：`domain=frontend` 等价于只启用"前端"列；`domain=all` 等价于前端+后端列并集
5. **custom 领域**：所有专项维度按 `○` 处理，完全由需求内容决定

## 每个维度的扫描模板

当某维度被启用且需求触及时，按以下四个角度展开测试点：

| 角度 | 说明 | 示例（以 T14 命令行接口为例） |
|------|------|------|
| 正向 | 该维度的核心功能按预期工作 | 正确参数组合返回预期输出和退出码 0 |
| 边界 | 该维度的极端/临界条件 | 参数超长、空参数、特殊字符参数 |
| 异常 | 该维度的故障/错误路径 | 无权限写入目标路径、依赖命令不存在 |
| 交叉 | 该维度与其他已启用维度的组合影响 | 命令行参数 + 文件系统操作（T15）的组合场景 |
