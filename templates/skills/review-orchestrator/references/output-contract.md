# 输出契约

## 通用表达

- 使用平台无关、可直接阅读的 Markdown 或纯文本。
- 不依赖特定编辑器、Agent 或审查平台的指令、标签或解析能力。
- 不要求固定章节；根据实际内容组织，但 findings 始终优先于补充信息。

## Finding 内容

每个精确问题应包含：

1. 严重级别和简短标题
2. 可定位的相对路径与起始行，例如 `path/to/file:line`
3. 具体影响及触发场景
4. 支撑判断的代码事实或推理
5. 可执行的修复方向；没有可靠建议时可以省略

可以使用自然段或列表表达，不要求套用固定模板。

## 输出顺序

1. 按严重级别从高到低列出 findings
2. 补充验证缺口和 residual risk
3. 仅保留少量高价值可选优化

空内容不单独成节。没有 `P0/P1` 时，明确说明未发现阻断问题，但不限定固定文案。

## 模式差异

### `fast`

- 优先输出阻断问题与验证缺口
- 高风险非阻断仅在非常明确时保留
- 可选优化建议最多 1 条

### `deep`

- 完整说明每个 finding 的位置、影响和依据；有可靠建议时补充修复方向
- 允许保留少量高价值 `P2`
- 跨领域改动需要显式写出契约一致性结论

## 严重级别

| 级别 | 含义 | 默认是否重点输出 |
| --- | --- | --- |
| `P0` | 明确会导致错误结果、数据破坏、严重回退 | 是 |
| `P1` | 高概率引发回归、契约不兼容、关键路径风险 | 是 |
| `P2` | 可维护性或健壮性风险，但暂不阻断上线 | 仅高置信时输出 |
| `P3` | 风格或低收益建议 | 默认不单独输出 |

## 汇总约定

- 同一根因的重复问题只保留一条
- 跨领域同一个契约问题，优先保留跨端版本
- 最终核心 finding 最多 10 条
