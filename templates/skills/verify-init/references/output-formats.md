# 产出格式规范

Phase 4 维护测试规则、项目文档、验证 agent 与读取入口。根项目和子项目使用相同的分类规则。

## 共用资产与事实源

先从当前作用域 AGENTS 和现有文件定位同主题资产。domain-init R4 与 verify-init 更新同一套
规则和文档；已有 `testing-strategy.md` 等文件就沿用，不并列创建重复的 `testing.md`。

配置和 scripts 是执行事实依据。门槛变更必须对应已确认要求并在配置中落成；文档引用配置，
不另抄一份数值。配置与既有约定冲突时报告差异，先对齐再修改，不静默选择较宽松的一方。

## 测试规则

缺失时写到当前项目 `.harness/rules/testing.md`。

```yaml
---
description: 编写或运行测试时，遵守本项目的测试约束。
globs:
  - "tests/**"
---
```

按实际技术栈与作用域调整 globs，不把它视为所有平台都会按需加载的保证。正文只保留有依据的
执行约束：适用范围、隔离要求、mock 边界、必要门禁、失败处理等。不强制章节数量、测试比例、
覆盖率值或命令名称；没有证据的建议先进入 review。

需要了解环境、执行入口或示例时，按明确条件链接到测试文档。原理与详细示例写入 docs，
低频但必须遵守的约束仍保留在规则中。已有内容按差异合并，不能整文件覆盖。

## 测试文档

复用已有测试说明，缺失时创建当前项目 `docs/testing.md`。按实际需要组织：

- 范围与现状：已检测、已补齐、已验证可运行及仍缺失的能力，分别标记。
- 框架与配置：链接实际 manifest、配置文件和测试目录。
- 执行入口：注明工作目录、对应 script 或原生命令、适用范围和环境前提。
- 验证说明：如何选择最邻近测试、读取结果、定位失败和收集证据。
- 示例与排障：必要的操作示例、环境准备及已知限制，不复制整个配置文件。

根项目记录共享入口与跨项目验证，子项目记录本领域的验证方式。配置归属与执行目录可以不同，
必须明确；共享依赖不重复安装，子项目的详细知识通过相对链接引用。

未实现、未验证的能力不能写成当前事实。官方文档获取失败时，仅维护有本地证据的内容，标明
未配置或未验证的部分；不得生成假定存在的 scripts、门槛或 framework config。

## test-verifier agent

写到当前项目 `.harness/agents/test-verifier.md`，已有则增量合并。

```yaml
---
name: test-verifier
description: 接收变更和验证目标，执行已有测试并报告结果与覆盖缺口。当需要验证代码改动时被调度。
model: sonnet
---
```

### 角色定义

验证执行者：把待验证声明映射到已有可执行测试，运行、判定并回报。不得新增或修改测试，也
不得修改被测逻辑；缺少可执行落点时报告缺口，补测试交给实施流程。

### 强制启动步骤

1. 读取适用的 AGENTS，按入口定位测试规则与 docs 测试说明，并核对当前 scripts/config。
2. 从 `git diff` / `git status` 确认识别范围，区分当前任务与已有用户改动。
3. 将验证目标映射到适用单测、API、e2e 或跨项目验证，记录工作目录与环境前提。
4. 检查已有测试是否覆盖目标；没有则报告待补测试及其预期，不自行写测试。
5. 在正确目录执行最邻近的已有测试，使用实际 script 或原生命令，不假设 `test:unit` 等存在。
   仅在改动风险或未解决疑点要求时扩大范围；缺能力时报告未验证，不凭猜测执行替代命令。
6. 提取 pass/fail/skip、失败用例、关键错误栈，区分回归、测试过时、环境问题和覆盖缺口。
7. blocker-first 回报，附工作目录、命令与结果摘要。

### 判定与回报

- 覆盖率只按适用配置和已确认要求判定，不能临时追加默认门槛。
- e2e 疑似环境抖动可重试一次，保留首次失败和重试证据；不得用重试隐藏失败。
- 阻断项最多展开 5 条，其余归类；中文结论，命令与标识保留原文。
- 已验证、失败、跳过与未验证分别说明，指出下一步修复方向；无执行证据不得宣布通过。

### 调用边界与用例衔接

没有可执行验证目标、用户明确选择人工验证时不调用。缺测试基建时报告缺口并指向 verify-init，
不自行安装。纯文档变更若有链接或契约检查，可运行对应已有检查。

用户要求验证 TC 编号时，把该 TC 的预期当作验证目标：已有测试覆盖则运行；未覆盖则报告
“缺可执行落点，需先实现测试”。不自动把整份用例文档翻译成代码。

## AGENTS 入口与质量检查

- 项目知识入口统一复用 `project`；在 `verification` 槽位引用实际存在的测试文档与读取条件，
  `routing` 槽位声明验证角色触发条件。不重建独立 `domain` 槽位。
- 已填槽位删除成对的 `harness:user` 边界注释与已用完的占位提示，保留正文及相邻框架内容；
  未填槽位保留占位。标记已清理时按章节增量更新，缺少入口才新增，不重复追加或重写执行契约。
- 迁移说明先写目标文件、核对语义与链接，再替换旧正文，保留有效约束与失败处理。
- 检查同主题资产没有重复、相对链接有效、执行目录正确、命令确实存在。
- 按授权执行最小验证并记录结果；无法验证时说明原因，不把检测到文件标为已验证可运行。
