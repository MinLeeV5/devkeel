01需求背景

为 harness CLI 增加远程遥测，记录哪些项目在用、调用了什么命令和 skill，用于了解产品使用情况。

目标用户

角色关注点
harness 维护者使用量、命令分布、skill 热度，指导迭代
CLI 用户无感知或可 opt-out

核心用例

用例描述
命令调用上报异步上报命令名、成功/失败、耗时
Skill 使用上报记录 skill 名称
匿名项目标识UUID v4 写入 config.yml
Opt-outHARNESS_NO_TELEMETRY=1 或 CI=true

边界

In ScopeOut of Scope
全部 6 个命令的调用统计用户身份信息
Skill 名称级统计命令参数/输入内容
异步非阻塞上报可视化仪表盘
Opt-out 机制离线缓存与重试

05规格清单

Capability: cli-telemetry

Requirement

Track command execution

CLI SHALL 在每个命令执行完成后异步上报遥测事件，包含 projectId、命令名、成功状态、耗时、CLI 版本和时间戳。

Scenario: Successful command execution

WHEN 用户执行 devkeel init 且命令成功完成

THEN 发送事件 command: "init", success: true 及耗时

Scenario: Network failure

WHEN 遥测端点不可达

THEN 事件静默丢弃，CLI 正常退出

Requirement

Track skill usage

CLI SHALL 在 skill 被调用时上报事件，包含 skill 名称。

Scenario: Skill invocation

WHEN 用户触发 domain-init skill

THEN 发送事件 skill: "domain-init"

Requirement

Anonymous project identification

CLI SHALL 在首次遥测事件时生成 UUID v4 作为项目 ID，持久化到 config.yml。

Scenario: First run

WHEN telemetry.id 不存在

THEN 生成新 UUID 并写入 config.yml

Scenario: Subsequent run

WHEN telemetry.id 已存在

THEN 使用已有 ID

Requirement

Opt-out mechanism

CLI MUST NOT 在用户 opt-out 时发送任何遥测。

Scenario: Environment variable

WHEN HARNESS_NO_TELEMETRY=1

THEN 不发送 HTTP 请求

Scenario: CI environment

WHEN CI=true

THEN 不发送 HTTP 请求

Requirement

Non-blocking execution

遥测 MUST NOT 阻塞 CLI 主流程。fetch 调用为 fire-and-forget。

Scenario: Slow endpoint

WHEN 端点响应 >5s

THEN CLI 正常退出，不等待响应
