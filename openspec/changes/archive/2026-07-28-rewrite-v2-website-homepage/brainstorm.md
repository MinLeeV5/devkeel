# 变更 Brainstorm

## 目标

将 Harness V2 官网收敛为一篇面向现有项目负责人和 Tech Lead 的单页长文，让未使用 Harness 的访问者理解其价值并进入快速开始；首页用“项目知识、渐进治理、反馈回路”解释 V2，并以可核验的竞品比较、项目改造结果和极简架构取代重复页面与重型方法论。

## 现状与问题

当前 V2 主站已经将 Direct、Harness Lite、Harness Full 作为主要叙事，但首页、工作流、架构、最佳实践和 V2 更新仍分别维护相近内容，导航要求新用户在多页之间自行拼接产品心智。首页首要 CTA 是“选择任务路径 / 查看 V2 更新”，更像文档导航而非采用入口；交互式路由台还要求逐项点击才能看全三条路径。

当前快速开始内容完整但过长，Agent 与手动路径都使用时间线展开；`domain-init`、`verify-init` 被埋在末端步骤中，没有形成“让项目可理解 / 让产出可验证”的核心价值。最佳实践仍单独维护 Paseo、Worktree 等可选方法论，增加重复事实源。

现有公开页面与数据边界如下：

| 页面或能力 | 当前行为 | V2 首页重写后的问题或价值 |
|---|---|---|
| `/`、`/index.html` | V2 首页，含 Hero、概览、交互路由台、工作流入口、快速开始、社区 | 需要成为唯一 V2 核心文章和首要转化入口 |
| `/workflow.html`、`/architecture.html`、`/best-practices.html`、`/templates-v2.html` | 分别解释流程、机制、实践与 V2 演进 | 内容重复，需退场并深链到首页对应章节 |
| `/changelog.html` | 版本事实和升级记录 | 保留为独立工具页，不进入文章侧栏 |
| `/stats.html` | V2 遥测数据 | 保留供内部使用，但不从公开导航、正文或页脚露出 |
| `/capability-inventory.html` | V2 能力清单 | 已无有效用途，删除 |
| `/sharing.html` | 旧技术分享 | 归档为 `/v1/sharing.html`，原 URL 保持兼容跳转 |
| `/v1/*` | V1 首页、统计和能力清单 | 全部保留，并继续提供 V1 技术分享入口 |

竞品公开资料核对基线：Harness 仅标识为 V2；Superpowers 使用 v6.2.0；Trellis 没有 GitHub Release，使用 CLI 包 v0.6.9；Matt Pocock Skills 使用 v1.1.0。比较服务“现有项目负责人建立可靠 Agent 工程体系”的选型，不表达绝对产品优劣。

## 核心用例

| 角色/调用方 | 触发场景 | 预期结果 | 关键边界 |
|---|---|---|---|
| 首次接触 Harness 的项目负责人 | 访问 V2 首页 | 首屏理解 Harness 让现有项目成为 Agent 能读懂、会执行、可验证的工程环境，并能直接进入快速开始 | 不用 Schema、artifact、applyRequires 等内部术语解释价值 |
| 正在比较 Agent 工程方案的 Tech Lead | 阅读现状与竞品章节 | 看到带版本号、星级与“怎么做 + 代价”的多维对比，理解 Superpowers、Trellis、Matt Skills 与 Harness 的各自适用场景 | 星级以现有项目适配度为口径；引用官方资料，不伪造性能测试 |
| 希望减少流程负担的高级模型用户 | 阅读渐进路径章节 | 一次看懂专项 Skill、Direct、Lite、Full 的选择和升级关系 | 使用静态决策图，不保留伪在线分类或逐项点击才能看全的交互 |
| 接手已有项目的负责人 | 阅读项目改造章节 | 理解 `domain-init` 先扫描原始项目并生成专属能力，`verify-init` 再增量补齐验证基建；看到可验证的改造前后产物 | 两者视觉并列、执行有序；均明确用户确认与 Review 门禁 |
| 准备采用 Harness 的用户 | 点击首屏“快速开始” | 滚动到首页快速开始，默认获得 Agent 执行入口，并能按需展开手动命令 | 不把“一条指令”写成品牌承诺；手动入口仍可发现 |
| 移动端或键盘用户 | 浏览长文、竞品表和两张图 | 能通过折叠章节导航定位；竞品表可横向滑动且维度列/产品标题可辨认；图有文字替代 | 不依赖颜色、Hover 或动画传达唯一状态；尊重 reduced motion |
| 历史 V2 链接访问者 | 打开旧详情 URL | 跳转到首页最相关锚点 | `/` 与 `/index.html` 均继续工作，旧链接不直接 404 |
| V1 用户 | 从 V2 顶栏进入 V1 或浏览 V1 站点 | 所有 V1 页面继续可用，技术分享从 V1 导航进入 `/v1/sharing.html` | 不重写 V1 内容与视觉，仅完成归档路径和导航兼容 |
| 内部维护者 | 直接访问 Stats 或 Changelog | Stats 仍可访问但不公开露出；Changelog 继续作为公开工具页 | 删除 V2 capability inventory；不删除 V1 对应页面 |

## 范围与验收

| 范围 | 内容 |
|---|---|
| In Scope | 重写 V2 首页及共享营销导航；实现六章长文、桌面侧栏/移动折叠导航、竞品比较表、两张 SVG 图、精简快速开始和飞书群卡片；退场四个 V2 详情页并重定向；删除 V2 capability inventory；将 sharing 归档到 V1 并更新 V1 导航；更新相关路由、测试和构建契约 |
| Out of Scope | 不改 Harness Templates V2 执行契约、Skills 行为、CLI 发布逻辑、遥测接口或 Changelog 数据；不重写 V1 页面正文和 Stats 页面；不提交、不发布、不部署；不虚构采用数据、效率指标或竞品性能结论 |

验收条件：

- Hero 使用已确认标题“让现有项目成为 AI Agent 能读懂、会执行、可验证的工程环境。”，主按钮为“快速开始”，次按钮为“了解 Harness”。
- 首页正文控制为约 6–8 分钟阅读量，侧栏只包含“现状与对比、Harness V2 的答案、渐进式任务路径、改造现有项目、工作原理、快速开始”六章。
- 痛点和竞品放在同一章节，核心推导为：强模型减少固定通用流程的边际收益，但仍需要项目知识、工程边界和反馈回路。
- 对比表至少覆盖现有项目改造、项目知识生成、验证基建、路径灵活度、流程/状态负担、跨会话记忆、端到端治理、跨平台复用和可定制性；桌面可扫描，移动端保留语义表格并横向滑动。
- 渐进路径使用静态图，同时展示专项 Skill、Direct、Lite、Full 及升级条件；实践只保留“明确结果与验收、邻近验证、按需增加流程”三条底线。
- `domain-init` 与 `verify-init` 成为核心双引擎，展示“先扫描原始项目、后补验证基建”的执行顺序和各自用户门禁，并提供不含虚构数字的改造前后例子。
- 工作原理只用一张图连接 `AGENTS.md`、`.harness/`、`openspec/`、代码与测试反馈，不展开目录树、CLI 全集或 Schema 细节。
- 快速开始默认展示 Agent 入口，手动路径折叠；末尾保留现有飞书群二维码，文案聚焦安装、实践与反馈。
- 视觉保留深色基底和绿色主色，转为克制的工程文章；桌面 sticky 侧栏、移动折叠导航、键盘焦点和 reduced motion 行为可用。
- 旧 V2 详情 URL 深链到首页对应锚点；`/v1/*` 保留，`/sharing.html` 跳转到 `/v1/sharing.html`；Changelog 保留公开入口；Stats 无公开入口但直达可用；V2 capability inventory 不再作为可访问页面注册。
- 相关 Web 测试、完整 Web 测试、Web 构建以及桌面/移动端浏览器关键路径验证通过。

|---|---|---|
| `web/src/pages/home.tsx`、`web/src/pages/home/` | 多个卡片/入口拼接 V2 首页 | 重组为文章 shell、六个章节、两张图、比较表、快速开始和社区收尾 |

| `web/src/routes.ts`、`web/server.ts`、页面注册 | 解析 V2/V1 React 页面和静态分享页 | 加入旧 URL 重定向契约、V1 sharing 静态路径；移除 V2 capability inventory 注册，保留 Stats/Changelog/V1 |

| `web/tests/` | 守护现有多页 V2 结构 | 改为守护单页信息架构、比较、图示、重定向、V1/Stats/Changelog 边界和移动端可访问行为 |
| OpenSpec change 图表源 | 当前不存在 | 使用 `architecture-diagram` 生成两份自包含 HTML+SVG 设计源，站点使用响应式内联 SVG 版本 |

## 方案方向与取舍

| 决策 | 已确认方向 | 取舍 |
|---|---|---|
| 首要转化 | 让新用户进入快速开始 | 不再用“选择任务路径 / 查看 V2 更新”作为首屏主动作 |
| 产品承诺 | 让现有项目成为 Agent 能读懂、会执行、可验证的工程环境 | 不用“一条指令”作为品牌承诺，安装便利只在快速开始表达 |
| 阅读模式 | 单篇线性文章 + 章节侧栏 | 不再做功能卡片拼盘或多页文档目录 |
| 比较方式 | 版本化星级选择指南，附“怎么做 + 代价” | 不做无口径胜负榜、雷达图或永久不变的绝对评分 |
| 路径表达 | 一次看懂的静态决策图 | 删除交互路由台，降低操作和认知成本 |
| 项目改造 | `domain-init` 与 `verify-init` 作为双引擎 | 展示并列但执行有序；保留用户确认/Review，不宣传无条件自动改造 |
| 图示 | 两张必要的深色 SVG 图 | 不增加装饰性流程图；对比继续用表格 |
| 方法论 | 只保留三条质量底线 | Paseo、Worktree、固定 TDD/Subagent/Commit/MR 不作为 V2 默认实践 |
| 页面生命周期 | 首页唯一维护 V2 核心叙事，旧详情 URL 深链 | 保留兼容 URL，但不保留重复页面实现作为事实源 |
| V1 | 完整保留并吸收技术分享 | 不把 V1 内容混进 V2 长文；V2 顶栏提供明确入口 |
| 辅助页面 | Changelog 公开、Stats 隐藏、V2 capability inventory 删除 | 发布事实与内部数据继续各司其职，不干扰转化 |
| 视觉 | 仓库索引式工程文章，深色/低饱和绿色 | 保留品牌连续性但减少发光、渐变和卡片；大胆点集中在侧栏与两张图 |

## 约束、风险与决策

| 类型 | 约束或风险 | 决策或应对 |
|---|---|---|
| 工作区 | 当前已有大量未提交 V2 官网改动，与本次范围高度重叠 | 将其视为起始素材，允许重写/删除重叠部分；不回退 V1、Changelog、Stats 或其他无关改动 |
| 竞品事实 | 公开产品持续更新，星级包含选型推断 | 产品标题链接官方资料并显示明确版本；描述只使用公开行为；Harness 只标 V2 |
| Harness 版本 | 当前模板/CLI 工作树仍包含 Beta 版本号 | 首页与对比只写 Harness V2，不把本地 Beta 号包装成稳定版本事实 |
| 长表移动端 | 四个产品和说明会超过手机宽度 | 保留语义表格，固定维度和表头、横向滚动与列吸附，并提供可见操作提示 |
| 图表来源 | `architecture-diagram` 强制产出自包含 HTML+SVG，而首页需要响应式组件 | 在 OpenSpec change 中保留自包含设计源，提取同一语义和视觉系统为 React 内联 SVG；首页不使用模糊位图或嵌套 iframe |
| 重定向 | 静态资源、Vite history fallback 与 React route 都可能处理旧 URL | 使用服务器/路由可测试的显式重定向或入口映射，不依赖仅在点击导航时生效的逻辑 |
| 内容漂移 | 单页仍可能与 Changelog、Stats、V1 相互覆盖 | 首页只讲当前价值和使用路径；Changelog 讲版本事实；Stats 仅内部；V1 完整隔离 |
| 可访问性 | 侧栏、横向表格和 SVG 容易依赖视觉 | 使用语义导航、当前章节文本状态、键盘焦点、SVG title/desc 或等价文本、非颜色标签和 reduced motion |

## 流程选择

本次重写跨首页组件、共享导航、公开路由、静态 V1 归档、测试和两份可复用图表源，需要简短持久化协调；但不改变 CLI/模板外部契约、不涉及数据迁移、安全风险或难以回退的线上状态，因此使用 `lite`。用户已逐项确认范围、内容、页面生命周期和实施边界，无需升级 Full。
