01

需求摘要

核心用例

  • UC1 首次发现更新 — 执行 inject-review/doctor 时，检测到新版本，CLI 提示 + 打开浏览器更新页
  • UC2 后续提醒 — 同一版本再次提醒时，仅 CLI 提示，不再打开浏览器
  • UC3 无更新 — 缓存过期拉取后发现无更新，静默不提示
  • UC4 网络失败 — npm view 超时或失败，静默降级跳过检查
  • UC5 无头环境 — 浏览器打开失败，仅 CLI 提示不报错

需求边界

In ScopeOut of Scope
• inject-review / doctor 命令集成
• 本地缓存管理（24h TTL）
• 版本比对与 CLI 提示
• 跨平台浏览器打开
• 频率控制（每天最多 1 次）
• 静默降级与错误处理 		• 修改 web/changelog.html 页面逻辑
• 提供禁用更新检查的配置选项
• 区分 major/minor/patch 版本类型
• 后台定时检查进程
• 强制更新机制

验收标准

  • ✅ 执行 inject-review 后有更新时显示黄色醒目提示
  • ✅ 执行 doctor 后有更新时显示黄色醒目提示
  • ✅ 首次发现版本时自动打开浏览器（changelog.html?from=X.X.X）
  • ✅ 同一版本后续提醒不再打开浏览器
  • ✅ 缓存 24h 过期后重新拉取最新版本
  • ✅ 网络请求失败时静默降级，不影响主命令执行
02

关键设计

人机交互时序

sequenceDiagram
    participant U as 用户
    participant CMD as 命令层
    participant UN as update-notifier
    participant Cache as 本地缓存
    participant NPM as npm registry
    participant Browser as 浏览器

    U->>CMD: 执行 inject-review / doctor
    CMD->>CMD: 执行核心逻辑
    CMD->>UN: checkAndNotify()
    UN->>Cache: 读取 update-check.json

    alt 缓存未过期（<24h）
        Cache-->>UN: 返回缓存版本
        UN->>UN: 本地比对版本
    else 缓存已过期（>24h）
        UN->>NPM: npm view（异步，超时 3s）
        NPM-->>UN: 返回最新版本
        UN->>Cache: 写入新缓存
    end

    alt 有更新
        UN->>CMD: 输出 CLI 提示（黄色边框）
        alt 首次发现该版本
            UN->>Browser: 打开 changelog.html?from=1.0.0
            UN->>Cache: 记录 notifiedVersion
        else 已通知过
            Note over UN: 仅 CLI 提示
        end
    else 无更新
        Note over UN: 静默
    end

    CMD->>U: 命令完成

旁路隔离策略

场景处理方式
缓存读取失败视为不存在，触发网络请求
网络请求超时（>3s）静默跳过，不更新缓存
浏览器打开失败仅 CLI 提示，不报错
缓存写入失败静默跳过，下次继续尝试
任何未预期异常整体 try/catch 吞掉
