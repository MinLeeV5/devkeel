01

需求与设计

需求摘要

维度内容
动机当前工作流演示按场景分 tab，缺少从"阶段分解"角度讲解为什么要拆分工作流的独立页面
目标用户潜在用户（理解理念）+ 已有用户（操作指引），页面兼顾两者
核心观点每次与 Agent 的会话就是 Spec → Code → Growth 三个环节，每个环节用上最适合的工具，产出最高质量
开场策略问题驱动——三个痛点（跳过 spec / 无门禁 / 无沉淀）引出解决方案
案例使用已归档 change add-telemetry 作为贯穿案例

三层模型

层角色职责
openspec流程编排器定义阶段、管理 artifact 依赖、驱动流转、归档沉淀
SuperPowers方法论工具库需求分析、苏格拉底提问、TDD、worktree、代码审查、原子提交、归档复盘
OMC / OMX运行时编排引擎自动选择引擎、调度 skill、多 agent 协调

三阶段子步骤

Spec 阶段（4 步）

子步骤做了什么产物
提问发散苏格拉底式提问 + 5W1H / SCAMPERbrainstorm.md
探索与设计扫描代码现状、梳理依赖、产出初步方案explore.md + design.md
方案定稿收敛为可执行方案，拆解任务清单proposal.md + specs/ + tasks.md
人工评审生成 human-review 报告，供人工阅读和决策human-review.html

Code 阶段（4 步）

子步骤做了什么关键点
运行时选择自动检测环境，选用 omc 或 omx按能力匹配，无需人工选择
隔离执行在 git worktree 中独立工作安全回退、并行开发
TDD 驱动实现先写测试 → 实现 → 测试通过把人类工程实践自动化
审查与提交review-orchestrator + commit skill质量门禁自动执行

Growth 阶段（3 步）

子步骤做了什么关键点
验证交付spec vs 实现一致性校验verify.md 记录结果
归档沉淀/opsx:archive 结构化归入知识库可检索、可追溯
知识回顾自动产出 retrospective后续会话可加载已沉淀上下文

交互设计

sequenceDiagram participant U as 用户 participant P as 页面 U->>P: 打开 workflow.html P->>P: 渲染 Hero + 三层模型 P->>P: 渲染 Step Indicator（Spec 高亮） P->>P: 渲染三个阶段 section U->>P: 滚动到 Code section P->>P: IntersectionObserver 触发 P->>P: Step Indicator 切换到 Code 高亮 U->>P: 点击 Step Indicator "Growth" P->>P: smooth scroll 到 Growth section P->>P: Step Indicator 切换到 Growth 高亮
