01

需求背景

让 devkeel init 区分主仓库和领域子仓库，领域子仓库只落对应领域模板（不含通用模板和 openspec），同时修复 CLAUDE.md / AGENTS.md 被无条件覆写的问题。

问题陈述

当前 devkeel init 存在三个核心问题：

  1. CLAUDE.md 被无条件覆写 — fs.writeFileSync 直接写入，用户精心编写的项目描述、API 文档引用等内容会被模板替换。detect.ts 中声称"追加 @AGENTS.md 引用"，但代码实际是全量覆写。AGENTS.md 同理。
  2. 无仓库类型区分 — config 只有 project.types（frontend/backend/other），没有"主仓库 vs 领域子仓库"概念。所有仓库走完全相同的 init 流程。
  3. 子模块初始化过于简陋 — 当前只创建 .gitkeep 存根和一行空白 AGENTS.md，不复制任何领域模板内容。

目标用户

角色关注点
主仓库维护者init 后所有子仓库都有正确的领域规范，不需要手动二次配置
领域子仓库开发者.harness/ 中的 skills/rules/agents 与自己的技术栈匹配，无多余噪音
CI/CD 工程师config.yml 中有明确的 repoType 字段，便于自动化流程判断

核心用例

用例 1：CLAUDE.md / AGENTS.md 智能覆写

场景行为
文件不存在写入完整模板
文件存在，内容与模板一致覆写为最新模板
文件存在，包含非模板内容只确保顶部有 @AGENTS.md 引用，不修改其余内容

用例 4：领域子仓库 init 流程

flowchart TD
    A[检测为领域子仓库] --> B[用户选择领域类型]
    B --> C[复制领域模板到 .harness/]
    C --> D[写入领域版 AGENTS.md]
    D --> E[智能写入 CLAUDE.md]
    E --> F[创建平台 symlink]

领域子仓库 不执行：复制通用模板、落 openspec 脚手架、复制 commands 目录。

需求边界

In Scope

  • CLAUDE.md / AGENTS.md 智能覆写（对比模板内容判断）
  • config.yml 新增 project.repoType（main | domain）
  • config.yml 新增 project.domainType（领域子仓库专用）
  • 仓库类型自动检测（基于 .gitmodules）+ 用户确认
  • 领域子仓库 init 流程
  • 主仓库 init 时批量为子模块选择领域类型并初始化

Out of Scope

  • setup skill 自动生成项目描述 — 后续迭代
  • 领域子仓库的 openspec 支持 — 明确排除
  • 主仓库/子仓库间的 config 继承或联动机制
02

变更提案

Why

当前 devkeel init 对所有仓库执行统一流程，存在三个痛点：(1) CLAUDE.md / AGENTS.md 被无条件覆写；(2) 无主仓库/领域子仓库的概念区分；(3) 子模块初始化只创建空存根。团队在多仓库场景下使用 harness-cli 已成常态，需要 init 命令具备仓库类型感知能力。

What Changes

变更项FromTo
CLAUDE.md 写入行为 fs.writeFileSync 无条件覆写 智能覆写 — 检测非模板内容则保留，只确保 @AGENTS.md 引用
仓库类型检测 config 只有 project.types 新增 repoType + domainType，基于 .gitmodules 自动检测
领域子仓库 init 创建 .gitkeep 存根 完整的领域 init — 复制领域模板 + 领域版 AGENTS.md/CLAUDE.md + 平台 symlink
子模块批量 init 只选择哪些子模块要 init 还需为每个子模块选择领域类型

Capabilities

新增能力

  • smart-file-write — CLAUDE.md / AGENTS.md 智能覆写机制
  • repo-type-detection — 仓库类型自动检测与交互确认
  • domain-subrepo-init — 领域子仓库 init 流程
  • domain-templates — 领域子仓库的 AGENTS.md / CLAUDE.md 模板

Impact

影响范围说明
src/commands/init.ts主要改动 — 流程分支、交互提示、子模块处理重构
src/lib/templates.ts新增 hasUserContent()、writeSmartFile()
src/lib/detect.ts新增 detectRepoType()
src/lib/config.ts接口扩展 repoType、domainType 字段
templates/新增 agents-md-domain.md、claude-md-domain.md

    D3 --> D4[创建平台 symlink]

智能覆写策略

在 src/lib/templates.ts 新增 hasUserContent(filePath, templateContent)：读取现有文件，渲染模板，去除 HTML 注释占位符后对比，有实质差异则返回 true。

写入策略函数 writeSmartFile(filePath, templateContent, ensureDirective)：文件不存在 → 写入完整模板；无用户内容 → 覆写；有用户内容 → 只确保 @AGENTS.md 引用存在。

04

规格清单

smart-file-write

Requirement

Smart file write SHALL detect user-authored content

系统在写入 CLAUDE.md 或 AGENTS.md 前，SHALL 将现有文件内容与渲染后的模板内容进行对比。去除 HTML 注释占位符后，如果存在实质性差异，则判定文件包含用户自定义内容。

Scenario: File does not exist

WHEN 目标路径不存在 CLAUDE.md 或 AGENTS.md

THEN 系统 SHALL 写入完整渲染后的模板内容

Scenario: File exists with only template placeholders

WHEN 文件存在且内容与渲染后的模板一致

THEN 系统 SHALL 覆写为最新渲染后的模板内容

Scenario: File exists with user-authored content

WHEN 文件存在且内容与渲染后的模板存在实质性差异

THEN 系统 SHALL 保留现有内容不做修改

Requirement

Smart file write SHALL ensure @AGENTS.md directive exists

当文件被判定包含用户自定义内容时，系统 SHALL 检查文件顶部是否包含 @AGENTS.md 引用指令。

Scenario: User content file missing directive

WHEN 文件包含用户自定义内容且顶部不包含 @AGENTS.md

THEN 系统 SHALL 在文件顶部插入 @AGENTS.md\n\n

Scenario: User content file already has directive

WHEN 文件包含用户自定义内容且已包含 @AGENTS.md

THEN 系统 SHALL 不做任何修改

repo-type-detection

Requirement

System SHALL auto-detect repo type based on .gitmodules

系统在 init 流程启动时 SHALL 检查 .gitmodules 是否存在且包含子模块条目。

Scenario: Project has .gitmodules with submodules

WHEN .gitmodules 包含至少一个 [submodule "..."] 条目

THEN 推断仓库类型为 main

Scenario: No .gitmodules or empty

WHEN 不存在 .gitmodules 或文件为空

THEN 推断仓库类型为 domain

Requirement

Config SHALL include repoType and domainType fields

HarnessConfig 接口 SHALL 包含 project.repoType（main | domain）。领域子仓库还需 project.domainType。

Scenario: Existing config without repoType

WHEN 读取已有 config.yml 且缺少 repoType

THEN 系统 SHALL 正常运行不报错（向后兼容）

domain-subrepo-init

Requirement

Domain sub-repo init SHALL only copy domain-specific templates

当 repoType 为 domain 时，只将对应领域模板的 skills/rules/agents 复制到 .harness/ 顶层。

Scenario: No generic templates or openspec copied

WHEN repoType 为 domain

THEN 不调用通用模板复制，不创建 openspec/ 目录，不复制 commands

Requirement

Main repo batch init SHALL use domain sub-repo logic

主仓库 init 时批量初始化子模块 SHALL 调用领域子仓库 init 逻辑，而非创建 .gitkeep 存根。

Scenario: Batch init with domain type selection

WHEN 主仓库 init 选择了子模块并指定了领域类型

THEN 对每个子模块执行领域子仓库 init 流程

domain-templates

Requirement

System SHALL provide domain-specific templates

系统 SHALL 包含领域子仓库专用的 AGENTS.md 和 CLAUDE.md 模板，支持 {{PROJECT_NAME}} 和 {{DOMAIN_TYPE}} 变量。

Scenario: Domain templates are simpler than main

WHEN 对比领域模板与主仓库模板

THEN 领域模板不包含 openspec 路由、子模块处理等主仓库特有内容
