## TL;DR

将当前单页 index.html 拆分为三份文档（首页 + 架构设计 + 最佳实践），首页聚焦"是什么 → 快速开始 → 工作流演示"，架构演进内容统一收入变更日志。

## 需求背景

当前 `web/index.html` 是一份大而全的单页文档，包含了从产品介绍到架构设计、CLI 命令、最佳实践、架构演进等所有内容。存在以下痛点：

1. **首页信息过载** — 开发者第一次访问时，最想知道的是"这是什么、怎么用、效果如何"，但需要滚动大量架构细节才能找到快速开始
2. **内容定位模糊** — 架构设计（核心架构、路由机制）与使用指南（快速开始、工作流）混在一起，不同阶段的读者找不到对应内容
3. **架构演进占据首页空间** — V1→V2 的演进历史对新用户无价值，应归入变更日志

## 目标用户与角色

| 角色 | 关注点 | 对应文档 |
|------|--------|----------|
| **首次接触的开发者** | 是什么？能干嘛？怎么开始？ | 首页 |
| **正在使用的开发者** | 工作流怎么用？遇到问题查什么？ | 首页（工作流演示）+ 最佳实践 |
| **深度用户 / 贡献者** | 架构如何运作？选型理由是什么？ | 架构设计文档 |
| **关注版本变化的用户** | 版本间有什么变化？ | 变更日志（已有 changelog.html） |

## 需求边界

**In Scope:**

- 拆分现有 index.html 内容到三份文档
- 调整导航栏，三份文档间可互相跳转
- 保持现有视觉风格（深色主题、CSS 变量）不变
- 将 V1→V2 架构演进内容迁移到 changelog.html
- 三份文档共享同一套 CSS（可考虑抽取公共样式）

**Out of Scope:**

- 不重新设计视觉风格或配色方案
- 不新增内容（Worktree + Setup 模式仅占位）
- 不改变现有工作流演示的 tab 交互逻辑
- 不涉及 web/v1/ 目录（旧版本保持不动）

## 探索过的替代方向

| 方向 | 取舍 |
|------|------|
| **保持单页，用更好的导航** | 不采纳 — 内容量太大，即使导航优化，首次访问的信息过载问题仍存在 |
| **使用静态站点生成器（VitePress/Docusaurus）** | 不采纳 — 当前是纯 HTML，引入构建工具增加维护成本，且文档量不大（3 页），纯 HTML 足够 |
| **拆成更多细粒度页面（每个 section 一页）** | 不采纳 — 3 页的粒度已经足够，过度拆分反而增加导航负担 |
