需求背景

将当前单页 index.html 拆分为三份文档（首页 + 架构设计 + 最佳实践），首页聚焦"是什么 → 快速开始 → 工作流演示"，架构演进内容统一收入变更日志。

痛点

  1. 首页信息过载 — 开发者第一次访问时，最想知道的是"这是什么、怎么用、效果如何"，但需要滚过大量架构细节才能找到快速开始
  2. 内容定位模糊 — 架构设计（核心架构、路由机制）与使用指南（快速开始、工作流）混在一起，不同阶段的读者找不到对应内容
  3. 架构演进占据首页空间 — V1→V2 的演进历史对新用户无价值，应归入变更日志

目标用户

角色关注点对应文档
首次接触的开发者是什么？能干嘛？怎么开始？首页
正在使用的开发者工作流怎么用？遇到问题查什么？首页 + 最佳实践
深度用户 / 贡献者架构如何运作？选型理由？架构设计文档
关注版本变化的用户版本间有什么变化？变更日志

Why

当前 web/index.html 是一份 1493 行的单页文档，混合了产品介绍、架构设计、CLI 参考、最佳实践和版本演进等内容。按读者角色拆分为三份独立文档，让每类读者直达所需内容。
