01

需求摘要

核心用例

用例触发预期
首次执行 update缓存为空npm view → 下载 tarball → 解压到缓存
重复执行且版本未变缓存命中复用缓存，不重新下载
模板包发布新版本latest 版本变化下载新版本，保留旧版本供回滚
网络/registry 不可达npm 调用失败报错退出，含修复指引

需求边界

In Scope

  • templates/ 就地升级为 devkeel-templates npm 包
  • CLI 新增 templates-cache.ts 封装拉取与缓存
  • getTemplatesDir/getBuiltinVersions/readSchemaVersion 指向缓存
  • devkeel update/init 入口前置 ensureTemplatesCache
  • 失败路径诊断文案（含 registry 配置指引）

Out of Scope

  • 另开独立仓库（直接复用 templates/）
  • 旧 CLI 兼容或 fallback
  • TTL 缓存 / 离线模式 / 异步后台刷新
  • lerna/changesets 协调

验收标准

  • pnpm lint 通过
  • pnpm test 通过（含新增 templates-cache.test.ts）
  • pnpm build 产物不含 templates/
  • devkeel update 在配置内部 registry 后可正常拉取模板
  • 网络失败时输出完整诊断文案并 exit(1)

关键设计

方案对比

维度A: runtime dependencyB: 运行时拉取（采纳）
"永远最新"语义受 caret 范围限制每次 update 必拉 latest
CLI 升版频率必须跟着模板升解耦
运行时依赖数+10（用环境 npm）
网络依赖仅 npm install 时每次 update/init

// src/lib/templates-cache.ts

export interface TemplatesCacheInfo {
  cacheDir: string     // ~/.harness/cache/harness-templates/<version>
  version: string      // 实际拉到的版本号
}

export class TemplatesFetchError extends Error {
  readonly diagnostic: string   // 人类可读的修复指引
}

export function ensureTemplatesCache(): TemplatesCacheInfo
// - 调用 npm view 拿 latest 版本
// - 与缓存 meta.json 比对，必要时下载解压
// - 失败抛出 TemplatesFetchError（含 registry 配置指引）

// src/lib/templates.ts 改造

let cachedTemplatesDir: string | null = null

export function setTemplatesDir(dir: string): void {
  cachedTemplatesDir = dir
}

export function getTemplatesDir(): string {
  if (cachedTemplatesDir) return cachedTemplatesDir
  // 本地开发 fallback
  const candidate = path.resolve(__dirname, '..', 'templates')
  if (fs.existsSync(candidate)) return candidate
  return path.resolve(__dirname, '..', '..', 'templates')
}
