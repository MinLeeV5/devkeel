## §1 新增页：什么是 Harness Engineering

### 位置

封面（第 1 页）之后、痛点页之前，成为新的第 2 页。总页数从 18 → 19。

### 叙事逻辑

引用 OpenAI 文章《工程技术：在智能体优先的世界中利用 Codex》（Ryan Lopopolo, 2026-02-11）的核心洞察，建立"Harness Engineering"的概念，然后自然过渡到痛点页。

### 页面结构

```
eyebrow:  // harness engineering
h2:       设计环境，明确意图，构建反馈回路

┌──────────────────────────────────────────────┐
│  主定义卡片                                    │
│  Harness Engineering 是一种工程方法论：         │
│  工程师不再亲手写每一行代码，                    │
│  而是设计让 AI Agent 高效工作的环境              │
│  —— 通过约束、文档和反馈回路，                   │
│  让 Agent 进入项目就知道该怎么做。               │
└──────────────────────────────────────────────┘

┌──────────┐  ┌──────────┐  ┌──────────┐
│ 🧭 编排   │  │ 📏 规范   │  │ 📚 沉淀   │
│ 给地图    │  │ 约束加速  │  │ 仓库即记忆 │
└──────────┘  └──────────┘  └──────────┘

底部金句: OpenAI 用 3 名工程师 + Codex，5 个月产出百万行代码。
         关键不是更好的 prompt，而是更好的 harness。
```

### 三根支柱卡片内容

| 支柱 | 标题 | 核心文案 |
|------|------|----------|
| 🧭 编排 | 给 Agent 一张地图 | "给 Codex 的是一张地图，而不是一本 1000 页的说明书" — 把工具和流程按正确顺序组合，让 Agent 知道先做什么、后做什么 |
| 📏 规范 | 约束是加速器 | "有了约束，速度才不会下降" — 通过架构边界和编码标准，让 Agent 快速交付而不跑偏 |
| 📚 沉淀 | 代码仓库即记忆 | "存储在聊天记录或人们头脑中的知识都无法被系统访问" — 所有经验归档到仓库，越用越厚 |

## §2 痛点页术语替换

### 改动内容

| 现在 | 替换为 | 描述调整 |
|------|--------|----------|
| ⚠️ 跳过 Spec | ⚠️ 没想清楚就开干 | 需求没想清楚就让 Agent 写代码，它按自己的理解实现，反复返工。 |
| 🚧 无门禁 | 🚧 没人检查就上线 | Agent 写完代码直接合入，没人帮它把关，低质量代码悄悄堆积。 |
| 🗑 无沉淀 | 🗑 做完就忘，反复踩坑 | 每次对话结束就清空记忆，同样的错误换个人、换个时间又犯一遍。 |

### eyebrow 微调

`// 为什么需要 harness` → `// 现状之痛`

### 底部金句保持不变

> Agent 能力很强，但它不了解你的项目——不知道该遵守什么规范、用什么工具、走什么流程。
